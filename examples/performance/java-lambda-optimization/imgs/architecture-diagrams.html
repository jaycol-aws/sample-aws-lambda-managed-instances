Key change from v1. The v1 framework recommended GraalVM Native for I/O-bound workloads based on a p50 advantage (102ms vs 147ms LMI). That advantage was an artifact of unequal memory allocation — GraalVM had 2× the CPU (2048 MB vs 1024 MB). With equal resources (2048 MB / 2 vCPUs for all modes), LMI wins p50 across all three workload types. GraalVM Native's AOT compilation helps cold starts (~800ms init) but does not produce faster warm execution than the JVM with JIT.

3. JIT warmup — Standard Lambda vs LMI

The JVM's C2 compiler needs sustained execution to profile and optimize hot methods. Standard Lambda environments are recycled before C2 kicks in. LMI instances persist — C2 reaches peak optimization.

Workload-dependent. JIT warmup is dramatic for CPU-bound (12.7×) and I/O-bound (11.9×) workloads where SDK marshalling, serialization, and HTTP client code become hot paths. It's negligible for memory-bound workloads (1.1×) where the bottleneck is allocation and GC, not computation loops.
